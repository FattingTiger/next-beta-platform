# 内部应用内测平台：服务端验收矩阵 V0.1

> 文档状态：开发前验收基线  
> 编制日期：2026-08-29  
> 依据：`docs/需求分析-V0.2-内测平台.md`、`PRODUCT.md`  
> 适用范围：服务端 API、Web 管理后台、文件存储、数据库、审计、监控、备份恢复与部署环境  
> 不包含：Android 客户端自身的界面与系统安装兼容性测试

## 1. 使用方式

本文把“功能已开发”改写为可重复、可留证、可独立复核的验收条件。文中的“必须”是首版发布门槛；“建议”不阻止首版发布，但应记录取舍。

实现可以调整 API 路径和内部数据结构，但必须提供一份从实际接口到本文逻辑接口的映射，且不能改变权限边界、状态规则和证据要求。

### 1.1 独立三轮测试的定义

三轮测试使用同一个候选构建版本，但分别执行、分别出报告，不能用上一轮的通过结论代替本轮证据：

| 轮次 | 目的 | 最低独立性要求 |
| --- | --- | --- |
| Round 1 | 功能、角色、对象级权限和数据不变量 | 使用固定初始化数据重新建库；API 自动化与后台人工验收均从头执行 |
| Round 2 | UI、可访问性、异常与恢复路径 | 使用独立浏览器会话和错误注入环境；覆盖加载、空、错误、过期与冲突状态 |
| Round 3 | 压力、安全、备份恢复及部署隔离 | 使用独立性能数据集；安全测试账号与恢复目标环境不得复用生产数据 |

任何修复都会生成新的候选构建号。修复权限、文件访问、认证或数据模型后，三轮全部重跑；只修复样式时至少重跑 Round 2，并对 Round 1 做后台主流程冒烟；只调整容量参数时至少重跑 Round 3。

### 1.2 发布硬门槛

以下任一项失败，不能靠总分抵消：

1. 未授权用户能枚举或访问应用、APK、Bug 或截图。
2. 被禁用账号或已撤销会话仍可访问受保护资源。
3. 未签名、包名变化、签名变化或版本代码未递增的 APK 能被发布。
4. 已发布 APK 能被原地覆盖，或数据库记录摘要与实际文件不一致。
5. 下架、停用下载或撤销组授权后，旧下载入口仍长期有效。
6. Bug 状态、回复或历史内容可被无权用户篡改，或状态时间线丢失。
7. 密码明文存储、全站未启用 HTTPS、密钥进入代码仓库或日志。
8. 备份无法恢复 APK、版本、Bug、截图之间的关联。
9. 部署或压力测试影响同机现有 sing-box 服务的进程、端口、配置、路由、防火墙或可用性。

### 1.3 完成证据包

每轮报告必须包含以下元数据，且不得包含明文密码、访问令牌、手机号全文或真实 Bug 截图：

- Git 提交 SHA、构建号、数据库迁移版本、部署配置版本。
- 环境、开始/结束时间、执行人或自动化任务 ID。
- 用例总数、通过/失败/跳过数；跳过项必须有负责人和补测期限。
- 机器可读报告（例如 JUnit/JSON）和人工验收记录。
- 脱敏请求/响应、数据库断言、对象摘要、截图、录像或监控图，按每条用例的证据列归档。
- 缺陷编号、严重级别、修复构建号和重测结果。

证据目录建议按 `test-results/server/<build>/round-1|2|3/` 组织。截图只能证明当时的视觉状态，不能单独证明权限、数据库一致性或接口正确性。

## 2. 待确认项与本矩阵采用的临时基线

下列产品问题尚未正式确认。为避免开发停摆，本矩阵给出保守默认值；产品决定改变后，应更新对应规则和测试数据。

| 编号 | 待确认事项 | 临时验收基线 | 受影响范围 |
| --- | --- | --- | --- |
| D-01 | 登录方式 | 手机号 + 密码；不开放注册、短信登录和自助找回 | AUTH 全部 |
| D-02 | 首次登录是否改密 | 首次登录强制修改管理员设置的初始密码；重置后再次强制 | AUTH-06、R1-04 |
| D-03 | Bug 基本内容可见范围 | 对当前有权访问该应用的测试用户开放标题、版本、状态和脱敏描述；提交人身份及截图默认仅提交人和管理员可见；管理员可把整条 Bug 设为受限 | BUG-04、R1-23、R2-16 |
| D-04 | 用户被移出测试组后能否看历史反馈 | 仍可从“我的反馈”查看本人提交的 Bug 和管理员回复；不能看应用资料、下载或他人 Bug | DIST-02、BUG-03、R1-13 |
| D-05 | 上传大小限制 | APK 512 MiB，单张图片 10 MiB，每个 Bug 1～5 张；全部由配置控制 | VER-01、BUG-02、R2-10、R3-12 |
| D-06 | 备份目标 | 每日备份，RPO 不超过 24 小时，RTO 不超过 2 小时；发布前完成一次隔离恢复演练 | OPS-03、R3-18 |
| D-07 | API 登录态 | 访问令牌不超过 15 分钟，续期会话不超过 30 天并轮换；禁用、重置密码和管理员“解除会话”均撤销全部现有会话 | AUTH-03、R1-03 |
| D-08 | Bug 是否允许快速关闭或关闭后重开 | 管理员可从待处理/处理中直接关闭，但必须给出结论；待验证只允许关闭或退回处理中；首版关闭后不重开，确需继续则管理员退回规则须另行确认 | BUG-06、R1-25 |
| D-09 | APK 临时下载入口有效期 | 单个入口不超过 10 分钟并绑定用户和版本；到期续传需重新鉴权后换取新入口 | DIST-04、R1-20、R3-11 |

## 3. 跨模块业务不变量

| 编号 | 必须始终成立的规则 | 证明方式 |
| --- | --- | --- |
| INV-01 | 手机号标准化后全局唯一；禁用用户保留历史 Bug、下载和审计关联 | 并发创建测试、数据库唯一约束证据、禁用前后关系计数 |
| INV-02 | 管理员与内测用户角色分离；普通用户不能调用任何管理接口 | 全管理接口角色矩阵、服务端 403/404 结果、审计记录 |
| INV-03 | 应用可见范围是用户所有启用测试组授权应用的并集；停用组不授予权限 | 组合数据集和四层 ACL 测试：列表、详情、Bug、文件 |
| INV-04 | 权限必须在每次请求时由服务端判断，不能依赖客户端隐藏或旧页面状态 | 撤权后复用旧资源 ID、旧页面和旧下载地址的测试 |
| INV-05 | 包名唯一且是应用稳定标识；同一应用只允许一个当前发布版本 | 数据库约束、并发发布测试、版本查询断言 |
| INV-06 | 后续版本包名和签名与首版一致，versionCode 严格递增 | APK 解析报告、正反例夹具和发布接口结果 |
| INV-07 | 已发布 APK 不可覆盖；保存 SHA-256、签名证书摘要、大小和上传时间 | 发布前后对象摘要与数据库快照；覆盖请求被拒绝 |
| INV-08 | 每个 Bug 绑定提交时的具体应用版本；应用更新后历史 Bug 不迁移版本 | 更新前后 Bug 关联查询和时间线证据 |
| INV-09 | Bug 内容开始处理后不可原地改写，只能追加回复；每次状态变化都写入时间线 | 并发修改测试、时间线条目和审计记录 |
| INV-10 | 下载开始和完成是两个状态；同一用户的真实重复下载保留为独立事件，网络重试不得制造重复事件 | 幂等键测试、数据库事件序列、后台去重人数统计 |
| INV-11 | “下载完成”仅代表客户端确认文件完成，任何界面、接口和报表不得称为“安装成功” | API 字段、后台文案和导出字段全文检索及截图 |
| INV-12 | 文件链接不永久公开、不可枚举，并在账号/组/应用状态改变后失效或再次鉴权 | 匿名、越权、过期、撤权、下架五组访问测试 |
| INV-13 | 业务时间以 UTC 保存，API 带时区；管理后台按配置时区展示 | 数据库存储、API 序列化和跨日筛选测试 |
| INV-14 | 管理员关键操作不可无痕完成，失败操作也记录操作者、对象、结果和原因码 | 审计 API、数据库记录及对应业务请求 ID |

## 4. 服务端完整功能清单与验收条件

## 5. 逻辑 API 验收合同

以下路径用于说明职责，不强制实现命名。实际 API 必须提供 OpenAPI 或等价机器可读合同，并能映射到每一项。

### 5.1 通用协议

- 所有业务接口只允许 HTTPS；HTTP 必须跳转或拒绝，且不得接收凭据。
- 未登录返回 `401`；已登录但角色不符返回 `403`。对客户端不可见的应用、Bug 和文件统一返回 `404`，避免确认资源是否存在。
- 校验错误返回 `422` 并包含稳定字段码；唯一性或状态冲突返回 `409`；限流返回 `429`；过大文件返回 `413`；类型不支持返回 `415`。
- 错误正文必须包含稳定 `error_code` 和 `request_id`，不得返回 SQL、堆栈、对象存储路径或账号存在性细节。
- 列表接口必须有稳定排序、分页上限和下一页标识；新增/删除并发发生时不得出现无限循环或同一页重复。
- 所有写接口记录操作者和请求 ID。Bug 创建、下载开始/完成等可能被网络重试的写操作支持幂等键。
- 状态更新使用版本号、ETag 或等价并发控制；陈旧写入返回冲突，不静默覆盖。
- 日期时间使用 ISO 8601 并带时区；服务端按 UTC 保存。
- 文件元数据包含大小、实际 MIME、SHA-256；展示 API 不返回内部路径或永久对象 URL。

### 5.2 认证与本人信息 API

| 逻辑接口 | 成功合同 | 必测拒绝路径 |
| --- | --- | --- |
| `POST /api/v1/auth/login` | 返回短时访问凭据、会话信息、角色和是否必须改密 | 密码错/用户不存在同形响应；禁用；限流；畸形手机号 |
| `POST /api/v1/auth/refresh` | 轮换续期凭据，旧续期凭据不可再次使用 | 过期、撤销、重放、禁用用户 |
| `POST /api/v1/auth/logout` | 当前会话撤销且幂等 | 已撤销会话重复提交不恢复 |
| `POST /api/v1/auth/change-password` | 校验旧密码或强制改密凭证；成功后撤销其他会话 | 弱密码、错误旧密码、重放 |
| `GET /api/v1/me` | 返回姓名、脱敏手机号、角色、启用组和账户状态 | 过期、禁用、普通用户字段越界 |

### 5.3 客户端消费 API

| 逻辑接口 | 成功合同 | 必测拒绝路径 |
| --- | --- | --- |
| `GET /api/v1/apps` | 只返回当前授权且上架的应用及当前版本摘要；支持搜索/刷新 | 停用组、撤权、下架应用不出现 |
| `GET /api/v1/apps/{appId}` | 返回资料、截图、当前版本、更新内容和允许公开的 Bug 摘要 | 猜 ID、撤权、下架后访问 |
| `POST /api/v1/apps/{appId}/versions/{versionId}/downloads` | 新建一次下载事件，返回事件 ID、短时下载入口、大小和 SHA-256 | 非当前版、停用下载、禁用用户、撤权、下架 |
| `POST /api/v1/downloads/{downloadId}/complete` | 幂等标记客户端确认完成，保留首次完成时间 | 他人事件、错误摘要/大小、重复回调 |
| `POST /api/v1/downloads/{downloadId}/failed` | 保存失败或取消原因，不将其记为完成 | 他人事件、已完成事件倒退 |
| `GET /api/v1/bugs?scope=mine` 或 `scope=app` | `mine` 返回本人；`app` 只返回当前应用授权范围内的脱敏字段 | 通过筛选参数越过应用授权 |
| `POST /api/v1/bugs` | 原子创建 Bug、版本关联和附件关联，网络重试不重复 | 无应用权限、错误版本、缺字段、图片越界 |
| `GET /api/v1/bugs/{bugId}` | 按基本内容/身份/附件/整条受限四级策略裁剪响应 | 非提交人读取截图、撤权后看他人 Bug |
| `PATCH /api/v1/bugs/{bugId}` | 仅提交人在待处理状态可修改允许字段 | 已处理、他人、改变应用/版本 |
| `POST /api/v1/bugs/{bugId}/replies` | 追加不可变回复并进入时间线 | 无权回复、空内容、修改历史回复 |
| `POST /api/v1/bugs/{bugId}/verification` | 提交人确认通过关闭，或反馈仍存在退回处理中 | 非提交人、非待验证状态、陈旧版本 |

### 5.4 管理 API

| 资源 | 至少包含的逻辑接口 | 关键合同 |
| --- | --- | --- |
| 用户 | `GET/POST /admin/users`、`GET/PATCH /admin/users/{id}`，以及启用、禁用、重置密码、撤销会话动作 | 无物理删除；手机号唯一；禁用/重置即时撤销会话 |
| 测试组 | `GET/POST /admin/groups`、`GET/PATCH /admin/groups/{id}`、成员和应用分配接口、`.../disable` | 多组并集；停用不删历史；成员/应用分配幂等 |

| 审计 | `GET /admin/audit-events` | 只读、稳定排序、脱敏、可按对象和请求 ID 关联 |

### 5.5 文件访问合同

1. 上传先创建受鉴权的上传会话，完成后由服务端重新检查文件头、结构、大小和摘要，不能相信浏览器提交的 MIME 或摘要。
2. 临时上传失败不得生成可发布版本或完整 Bug；孤立临时对象有可验证的清理策略。
3. APK 下载入口仅绑定一个用户、应用版本和短有效期。若存储层签名 URL 无法在撤权后立即失效，则有效期必须足够短，且下载前置网关需再次鉴权。
4. 图片缩略图与原图权限一致；缩略图不能成为公开旁路。
5. Range 请求不得绕过到期和权限校验，合并后的文件 SHA-256 必须等于发布摘要。
6. 对象名称不得包含用户原始文件名或手机号；响应下载名需安全编码，阻止路径穿越和响应头注入。

## 9. Round 3：压力、安全与恢复测试矩阵

### 9.1 性能数据与默认阈值

压力库使用合成数据：100 个用户、12 个测试组、20 个应用、每应用 5 个历史版本、1,000 条 Bug、10,000 条下载事件、每个 Bug 0～5 张合成图片；不得使用真实员工数据或真实敏感截图。文件夹具至少包含 20 MiB、100 MiB 和 300 MiB 的有效签名测试 APK。

默认性能门槛（不含实际文件传输时长）：

- 30 并发用户持续 30 分钟，读写比例约 80:20：列表/详情 p95 ≤ 800 ms，管理写接口 p95 ≤ 1,200 ms，HTTP 5xx < 0.1%，业务断言失败为 0。
- 100 个账号在 120 秒内完成一次登录和应用列表刷新：成功率 ≥ 99%，未触发针对正常分散请求的全局误限流。

- 60 分钟混合耐久测试无 OOM、死锁、连接池耗尽或持续增长的队列；最后 30 分钟内存基线漂移不超过 15%，或提供可解释且有上限的缓存证据。

若目标服务器与 sing-box 共机，生产机测试流量必须先依据空闲带宽设上限，不能以压满网卡的方式验证极限容量。极限吞吐在隔离环境测试；生产机仅做有界容量确认和 VPN 无回归验证。

## 12. 当前关键遗漏风险

1. **身份方案尚未封板。** 手机号 + 密码、首次强制改密和会话模型目前是临时基线；如果改成短信验证码，限流、成本、可用性和账号恢复测试需要重写。
2. **Bug 可见性尚未正式确认。** 基本描述、提交人身份、截图和整条受限是四种不同权限；只做一个 `isPublic` 字段无法满足当前隐私边界。
3. **服务器端无法可靠证明安装成功。** 下载完成回报来自客户端，只能作为“客户端确认文件完成”；产品、API 和报表必须持续使用这个口径。
4. **APK 签名运营责任未确定。** 平台只校验证书摘要，不托管私钥；稳定测试签名的负责人、备份和丢失处置仍是发布外部依赖。
5. **文件存储与撤权模型尚未决定。** 本矩阵暂按 10 分钟入口验收；直接发较长对象存储签名 URL 会形成撤权窗口，需在短有效期和下载网关二次鉴权之间做明确选择。
6. **备份只备数据库不够。** 必须同时备份文件对象和索引，并以 SHA-256 验证恢复；否则数据库恢复成功仍可能出现截图或 APK 错配。
7. **共享服务器存在变更半径风险。** 应用部署、反向代理、端口、防火墙和压力流量都可能影响 sing-box；必须先做只读基线、资源与端口隔离，并把 VPN 探针纳入发布门槛。
8. **上传边界和保留周期未确认。** APK/截图大小、临时文件清理、下架文件保留、审计和备份保留期限需要在生产配置前确定。
9. **域名、证书、邮件/短信之外的账号交付渠道未确定。** 这会影响 HTTPS 验收、初始密码安全交付和证书监控。
10. **“管理员”人数和账号恢复机制未定义。** 即使首版只有一种管理员角色，也应避免共享账号，并确定唯一管理员锁死时的受控恢复流程。
11. **Bug 状态机的快捷关闭和重开规则未正式确认。** 本矩阵允许管理员带结论快速关闭、将已关闭设为终态；如果业务要求重开，时间线、通知和权限用例必须扩展。
